Encrypting the Arsenal

Each exploit record's sensitive fields are encrypted individually with unique AES-256 keys via FLE.

exploit-vault-demo.mjs SDK Script 
// Generate unique key per record
const keyId = newRecordKeyId();

// Encrypt each sensitive field with FLE
const enc = {
  codename:  ex.codename,  // plaintext
  cve:       ex.cve,       // plaintext

  description:   await encryptField(
    ex.description, keyId
  ),
  payload_notes: await encryptField(
    ex.payload_notes, keyId
  ),
  analysis:      await encryptField(
    ex.analysis, keyId
  ),
};

// Output: CY41GHFLE<keyId>...
// Nomadic ciphertext that carries
// its own key reference

Authorized Analyst Reads

The clerk role requests decryption. The CSA checks its grant table and releases the key.

Against Emerging Threats

Encryption That Outlasts the Attack

FLE uses AES-256 per field. The encryption is designed to remain resilient against both current and emerging threats.

Unique Key Per Field

Compromising one key reveals one field value — not the record, not the table, not the database.

Post-Quantum Resilient

AES-256 maintains 128-bit security against Grover's algorithm. Quantum computing does not break the field encryption.

Harvest-Now, Decrypt-Later

Intercepted ciphertext remains sealed. Future quantum capability does not retroactively expose AES-256 protected fields.

Nomadic Ciphertext

Protection travels with the data. Copied, exported, or backed up — the ciphertext stays sealed wherever it goes.
